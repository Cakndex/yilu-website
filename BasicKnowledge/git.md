# Git 与代码协作

Git 是一个版本管理工具，用来记录代码在不同时间点的变化。它可以回答几个很常见的问题：哪一行被改了、谁改的、什么时候改的、能不能回到之前的版本。

## 为什么需要 Git

只保存一份代码时，很容易出现 `final.c`、`final-v2.c`、`final-真的最后一版.c` 这样的文件名。多人协作时，还可能互相覆盖修改，最后无法判断哪一份才是最新内容。

Git 通过提交记录保存每次变化，让代码历史可追踪，也让不同人可以基于同一份项目继续工作。

## 先掌握这些概念

- **仓库**：被 Git 管理的项目目录。
- **提交**：一次有说明的代码变化记录。
- **分支**：从某条开发线路分出来的独立工作空间。
- **远程仓库**：放在 GitHub、Gitee 等平台上的共享版本。
- **合并**：把一条分支上的修改整合到另一条分支。

初学阶段不需要记住所有命令，先知道每个概念解决什么问题更重要。

## 基本工作流

一个简单的日常流程通常包括：

1. 查看当前修改了哪些文件。
2. 把准备提交的内容加入暂存区。
3. 编写清楚、简短的提交信息。
4. 提交到本地仓库。
5. 根据需要推送到远程仓库。

提交信息可以写成“实现登录接口参数校验”“修复表格在小屏幕下溢出”这样的具体描述，避免只写“更新”“修改”或大量重复的“submit”。

## 分支和协作

多人协作时，不建议所有人长期直接修改同一条主分支。更常见的方式是为一个功能创建分支，完成后再通过 Pull Request 或合并请求接受检查。

合并前至少要确认：

- 代码是否能够在自己的环境中运行。
- 是否意外提交了密码、密钥或无关文件。
- 提交信息能否说明这次修改的目的。
- README 或配置是否同步更新。

## GitHub 的作用

GitHub 是常用的 Git 远程托管平台。可以把代码保存在仓库中，也可以查看历史、提出 issue、参与开源项目或展示个人作品。

对于招新和项目实践，GitHub 仓库可以作为代码与学习记录的统一入口。即使暂时没有使用 GitHub，也建议先理解 Git 的基本工作方式，再选择 Gitee 等其他平台。

## 养成可回退的习惯

不要在项目完全不同、无法运行时才做一次巨大提交。每完成一个明确的小功能，就提交一次，并保留可以运行的版本。这样出现问题时，能够快速定位修改范围，也更容易和别人协作。
